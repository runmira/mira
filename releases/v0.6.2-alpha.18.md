# Mira desktop 0.6.2-alpha.18

A steadier chat stream, external subagents in Mira's agent panels, and stronger session recovery.

## Highlights

- **Steadier scrolling.** Streaming replies and expanding tool groups preserve your reading position, with consistent row alignment and spacing.
- **Thinking stays compact.** Long reasoning scrolls inside a bounded block, while collapsed blocks show a live preview. Activity summaries animate as work progresses, and command output stays still while you read older lines.
- **External subagents in Mira.** Codex children, OpenCode ACP child sessions and Claude child activity use Mira's agent cards and panels, with separate reasoning, replies and tools when the provider supplies them.
- **Safer chat switching and reconnects.** Session-owned requests and bounded stream replay help keep activity in the correct chat and recover retained events after connection interruptions.
- **Lower idle memory use.** Unused browser sessions shut down after 15 minutes, idle chat slots leave memory safely, and production builds omit frontend source maps.

## Fixed

- Turn-ended notices stay visible outside collapsed activity groups. Only the final agent reply carries its time row.
- Late external child identifiers no longer create duplicate agent cards or break open child panels. Child activity and lifecycle data persist for transcript replay.
- Approved tools move from pending to running when their tool-start event arrives.
- Follow-up turn completion, delayed approval responses, settings-load errors and stale authentication retries retain the correct owner and state.
- Session cleanup protects active, attached and pending work; background processes keep their chat available until exit.
- Context, repository, file and integration requests capture their chat instead of following a changing global selection.

## Under the hood

- Shared runtime, resources and workspace state now have explicit owners, with streaming updates isolated from stable shell state.
- New clients use session IDs, epochs and sequences for bounded reconnect replay. Older clients retain the original event protocol; expired cursors or server restarts recover from a snapshot.
- The eager frontend bundle is 373.0 kB gzipped, below the existing 400 kB budget. Authentication loads its SDK separately during configured startup.
- Development desktop launches use the freshly built server.

## Testing notes

- Frontend, provider and server regressions, production build, bundle limits, formatting and workspace Clippy passed before the merge.
- Full child streams depend on provider support. Providers that expose only progress or results continue to show those; unfinished exposed activity pauses when the parent turn ends.
- Live authenticated desktop/provider acceptance remains separate from automated checks.
