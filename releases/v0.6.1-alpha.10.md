# Mira v0.6.1-alpha.10

A calmer sidebar, clearer recovery when a request fails, and settings you can
navigate directly. Underneath, Mira reuses more of the conversation cache and
gives agents a map of larger repositories before they start exploring.

These notes cover everything since `desktop-v0.6.1-alpha.9`, through the
frontend and settings refactor in #181.

## Highlights

- **A sidebar that keeps work in view.** Attention and recent chats are easier to find; completed work moves into a Settled shelf. New chat, project search and filters stay within reach as you scroll.
- **Know what to do when a request fails.** Chat errors explain provider limits, connection problems and sign-in failures, with retry or settings actions where appropriate.
- **Settings with proper navigation.** Each section has its own link and loads on demand. Back and forward work, and unsaved settings survive switching sections.
- **More of your prompt served from cache.** Conversation caching now includes Anthropic and supported OpenRouter providers, with steadier memory placement and fewer rewrites of old context.
- **Agents start with a repository map.** Larger Git repositories get a compact source map at session start; the agent can ask for more detail with the new `repo_map` tool.

## New

- **Repository maps:** source outlines for Rust, TypeScript/JavaScript, Python
  and Go, ranked to surface useful definitions. Git worktrees with at least
  25 source files receive a compact map at session start. Maps are cached
  outside the repository; `MIRA_REPO_MAP=0` disables automatic inclusion.
- **Cache visibility:** the usage popover shows the share of input served
  from cache and the most recent explanation when a large prompt reused
  little of it, such as changed tools, an earlier message edit or expiry.
- **Sidebar shelves:** recent chats across projects, chats needing attention,
  and a collapsible Settled shelf for completed work. Chats can be settled
  or brought back manually; writing to a settled chat brings it back.
- **Pull request marks:** worktree chats show their open, draft, merged or
  closed pull request, with a shortcut to open it.
- **Evals:** seven additional working task fixtures, cache share and cost in
  results, clearer provider failure reports, and a Claude Code runner with
  `mira eval --agent claude [--agent-model haiku]`.

## Improved

- Sidebar rows separate titles from status, branch and time details. Pull
  request marks sit at the right, background actions live in a submenu, and
  search, project headings and light-mode selection styling are clearer.
- Sticky sidebar controls have an opaque surface and a soft edge, so
  scrolling rows do not show through them.
- Settings sections have direct URLs, shared draft state, browser history
  navigation and individual loading-error recovery.
- Transcript rendering loads on demand. Initial JavaScript is about
  346 kB gzipped, within the existing 400 kB budget.
- Anthropic requests cache recent conversation messages as well as the
  system prompt and tools. Supported OpenRouter requests receive the
  conversation cache markers too.
- Memory is chosen once per turn and saved with that prompt. Superseded
  successful file reads and old screenshots are trimmed in batches, reducing
  changes to the cached conversation prefix.
- Claude Code avoids duplicate Mira file and shell tools, loads MCP tool
  definitions when needed, and only lists device tools when available.
- The frontend's workspace, composer, sidebar, panels, settings and API code
  are split into focused modules, with an automated 1,000-line source limit.

## Fixed

- Failed chat turns offer recovery for provider limits, authentication,
  timeouts and interrupted streams. Partial answers remain visible; retry
  targets the failed turn's opening message.
- Sidebar loading and persistence failures and settings load/save failures
  are surfaced with recovery actions instead of failing silently.
- Native title tooltips no longer duplicate the chat preview on hover.
- Sidebar settling, pull request discovery, sticky controls and live status
  updates handle the reviewed edge cases more consistently.
- Live checkpoint writes are serialized, and tests cover restoring context.
- Cache-hit updates clear stale cache-miss explanations. Failed or unfinished
  edits do not discard an earlier successful read.
- Memory and hook context stay attached to their turns across resume and
  rewind. User-written context tags remain intact and injected memory does
  not feed itself back into memory selection or learning.
- Device tool availability is checked again after a minute when no devices
  were initially available.
- `mira-acp` inherits the workspace version, keeping release versions aligned.
