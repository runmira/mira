# Mira v0.6.1-alpha.9

Use Mira from your phone: pair it with a code, reach your computer from any
network with one switch, and get a layout made for a small screen. Also an
approval queue with editable rules, multiple accounts per provider, and a
web UI that opens about three times lighter.

## Highlights

- **Mira on your phone.** Pair a phone or another computer by scanning a code, then check progress, answer approvals and send follow-ups from it. Paired devices are listed in Settings → Devices, where you can revoke them.
- **Reach Mira from anywhere.** One switch in Settings → Devices gives your computer a private address that works from any network. There's nothing to install or configure, and pairing still decides who gets in.
- **Made for small screens.** At phone size the sidebar becomes a drawer, panels open full screen, the composer stays above the keyboard, and approvals get big buttons.
- **Approval queue.** Waiting approvals are grouped, with Approve all / Deny all, and "Always allow" lets you edit the exact rule before it's saved.
- **Several accounts per provider.** Add a second key or agent account under `engines:` in `mira.yaml`, and changes apply without restarting.
- **Faster to open.** The web UI's first load dropped from about 1.2 MB to under 400 kB, and long chats with images open in a fraction of the time.
- **Early releases.** The update popup can show and install Alpha and Beta builds, with their notes, before you switch.

## New

- **Device pairing.** Anything that isn't this computer pairs before it can
  use Mira. Settings → Devices shows a QR code and an 8-character code,
  valid for 10 minutes. Wrong guesses are limited. Each paired device is
  listed with when it was last seen, and can be revoked.
- **Remote access** (Settings → Devices → *Reach Mira from anywhere*):
  - Gives this computer a stable `https://m-….runmira.dev` address. The
    connection dials out from your computer, so nothing is opened on your
    network.
  - Needs you signed in to Mira. Up to 5 computers per account.
  - The address alone grants nothing: every device still has to pair.
  - If Mira restarts on a different port, the address follows it.
- **Phone layout:**
  - The sidebar is a slide-out drawer, and every page has a button to
    open it.
  - The right panel opens full screen.
  - The composer is one row (attach, model, mode, send) and stays above
    the keyboard. Notches and the home indicator are respected.
  - Diffs scroll sideways, and side-by-side diffs show unified.
  - Text fields no longer zoom the page when tapped.
- **Touch:** approval choices are full-width buttons, controls that only
  appeared on hover are always shown, and a chat's status and menu sit
  side by side in the sidebar.
- **Approval queue:** pending approvals grouped by tool and folder, with
  how long each has waited, per-call selection, and Approve all / Deny
  all. "Always allow" opens the exact rule Mira would save, which you can
  edit; invalid rules are caught before anything is approved.
- **Engines** (`engines:` in `mira.yaml`, see `docs/engines.md`):
  - Several accounts per provider or agent, each with its own key.
  - Background jobs (titles, summaries, memory) can use any instance's
    model.
  - Prompt caching set per instance, with cache writes counted in cost.
  - Health shown in the model picker.
- **Codex:** Undo rewinds Codex's own conversation instead of starting it
  over. Codex chats get titles, and their context usage matches Codex's own.
- **Device tools:** agents can drive the iOS Simulator and Android
  Emulator.
- **Browser recording:** agents can record the browser as a GIF.
- **Compaction card:** shows progress while a long chat is summarized, how
  much it saved, and the summary itself.
- **Command output:** colors from the terminal are shown, output over 50
  lines folds to its first and last lines, exit codes are shown, and the
  command or its output can be copied.
- **Agent keys and settings live in Mira's server config**, written with
  owner-only permissions, and can come from environment variables. Settings
  saved in the browser before are moved over automatically.
- **Early releases** in the update popup: check Alpha and Beta, read their
  notes, and install one through the signed updater.
- **CLI** (with the next CLI release): `mira service install` keeps Mira's
  web UI running in the background and starts it at login, and
  `mira update` installs the latest release after checking its checksum.

## Improved

- The web UI's first load is about 394 kB instead of 1.2 MB. Settings,
  plugins, the review drawer, panels, the terminal and code highlighting
  for less common languages load when first needed, and are fetched early
  when you hover what opens them.
- Chat history loads in pages and images are fetched separately, so a
  3.4 MB chat opens as 7 kB. Responses are compressed.
- Rebuilt on React 19 with the React Compiler, so less of the UI redraws
  while an agent streams.
- A part of the app that fails to load shows a Retry instead of blanking
  the window.
- The install script checks the download's checksum.

## Fixed

- **Security:** web pages open in your browser could talk to Mira's local
  server. Requests now have to come from this computer or a paired device.
- Screenshots taken by tools were missing when a chat was reopened.
- Checkpoints missed edits that kept a file's size and timestamp the same.
- Copying an update command failed silently when the clipboard was
  blocked.
