# Mira desktop 0.6.2-beta.1

The first 0.6.2 beta brings steadier conversations, reliable agent selection and native OpenCode steering.

## Highlights

- **Follow the live reply.** Staying at the bottom keeps streaming output in view, including after a downward scroll gesture. Scrolling up preserves your reading position; returning to the end resumes following.
- **OpenCode steering.** Steer admits queued input into an active OpenCode v2 conversation without cancelling the turn. Disconnected attempts keep the message queued with visible feedback.
- **A dependable model picker.** Only enabled providers and agents appear, in stable alphabetical sections. Models have vendor icons and readable names, and the selected provider or agent stays beside the model name.
- **External subagents in Mira.** Codex, Claude Code and OpenCode child activity uses Mira's agent cards and panels. Child replies, reasoning and tools remain separate when exposed by the provider.
- **Clearer, steadier transcripts.** Thinking uses a bounded scrolling block with a live collapsed preview, turn-ended notices stay visible, and rows share consistent alignment. Click elsewhere to clear text highlighting.

## Fixed

- Empty new chats no longer show a context handoff before a conversation exists. Chat engine and instance choices persist across reloads.
- Model changes on the same agent preserve its conversation. Replacement runtimes validate before retiring the working agent; rejected choices retain the previous selection.
- Failed or dispatched inputs no longer appear as messages waiting for a turn, and one failed queued message no longer stalls later inputs.
- External-agent settings retain pending and failed discovery rows and finish their loading sweep. Provider-key status is scoped to provider settings.
- Sidebar elapsed time advances, the original active-turn spinner rotates, and folders and chats retain creation order while Recents tracks activity.
- Transcript virtualization attaches its scroll owner on initial mount, preserves reading anchors through row growth and limits disclosure pinning to actual transcript controls.
- Session-owned requests, reconnect replay and runtime replacement fencing keep delayed events in their owning conversation.

## Under the hood

- OpenCode v2 steering uses its plugin session API inside the ACP-owned server, with an authenticated loopback bridge, admission deduplication and lifecycle cleanup. Legacy HTTP-capable OpenCode releases retain their control path.
- Shared frontend runtime, resource and workspace state has explicit owners. Replay and idle runtime cleanup reduce retained work and memory.
- This beta includes the 0.6.2 alpha stream, queue, child-agent and recovery changes plus PR #193 and the bottom-follow correction.

## Testing notes

- Frontend regressions, production build and bundle/module limits passed for the bottom-follow correction.
- PR #193 passed frontend/server regressions and Clippy. Installed OpenCode v2.0.22 passed real ACP startup and a live free-model steering test without cancellation.
- Full packaged desktop acceptance across authenticated providers remains to be tested. Child-stream detail depends on what each provider exposes.
- OpenCode desktop and CLI versions may use different credential stores; Mira uses the configured CLI's saved login.
